## 3. API Endpoints Consumed

- `GET /api/tasks/project/:projectId`: Fetch root tasks for a project (`parentTaskId: null`).
- `GET /api/tasks/:id/subtasks`: Fetch subtasks for a parent task (`parentTaskId: parentTask._id`).
- `POST /api/tasks`: Create root task.
- `PUT /api/tasks/:id`: Update task details, status, or assignment.
- `DELETE /api/tasks/:id`: Soft delete task.
- `POST /api/tasks/:id/subtasks`: Create subtask under parent task.
- `POST /api/tasks/:id/comments`: Post task comment.

## 4. Hierarchy & Reward Policy Enforcement

- **Task Hierarchy:** `Project` $\rightarrow$ `Milestone` $\rightarrow$ `Task` $\rightarrow$ `Subtask` is clearly visually represented.
- **Reward Policy:**
  - Assigned Task/Subtask: Completion reward goes to `assignedTo` user.
  - Unassigned Task/Subtask: 0 reward points granted.
  - Reopening & re-completing: Idempotent (0 points re-awarded).
